# Domain docs

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

## Before exploring

Read the root glossary and ADRs relevant to the area being explored.

If these files do not exist, proceed silently. Do not suggest creating
them upfront; domain-modeling creates them when terms or decisions
are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
Avoid synonyms the glossary explicitly excludes.

If a needed concept is missing, reconsider the terminology or note
the gap for domain-modeling.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR, identify
the ADR, and explain why reopening the decision may be warranted.
